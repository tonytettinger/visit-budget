Architecture

Local Chrome enforcement with pure budget decisions at the centre.

System map

Modules and boundaries

2026-09-13
Core

Rule matching, budget transitions, migration, and local-day reset. It does not call Chrome APIs or manipulate the DOM.

Service worker and platform

Serialised browser events, storage, permissions, alarms, blocking reconciliation, and typed messages. These layers do not duplicate product decisions.

UI and content guard

Popup, options, blocked page, and in-page overlay render worker decisions. The guard preserves the page DOM beneath a block.

Data and flow

2026-09-13

A rule is one of a visit budget, time budget, or permanent block. Daily usage stays in local storage. A running active-time segment starts in session state so service-worker suspension can be settled but a full browser restart does not keep charging time.

Tab, focus, navigation, startup, permission, and alarm events first settle the active segment, then update state, blocking, badge, and guard. There is no server, account, telemetry, remote code, or third-party analytics.
